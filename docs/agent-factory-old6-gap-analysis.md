## 怎么办 — 通往"生成老 6 个级别真代码"的三步路线

**第一步：接上已建未接线的资产（最便宜，先做）**
- P2.5 函数测试器 `testGeneratedFunction`（worker/process/Docker 三档隔离，`apps/api/src/services/agent-factory/function-tester-run.ts`）已建成但**零调用点**——接进大脑循环，design 后自动 harness 测 `.ts` 交付物。

- module-runner 的依赖 `allowlist` 机制已存在但休眠（三档隔离层都支持）——开放受控依赖面（node:crypto、参数化 SQL、safe fetch），解决"所有 import 解析为 {}"。

**第二步：槽位填充 codegen（P1b，核心缺口）**
- `renderTsFunctionModule` 的三个 `#SLOT`（fieldMapping 直通 / classifyError 恒 park / controlFlow 仅注释）用 `codegen_agent` + 黄金范例填充——**老 6 个文件本身就是范例库**（错误分类学、按 JR 扇出、信封解包的真实样板）。
- 真 typecheck（`ts.createProgram --noEmit` 替换 transpile-only 语法检查）+ 测试发射：finish 时把已批准 TestCase + 沙箱真实 I/O 渲染成每 agent 一份 `<slug>.test.ts`（复用已有 `harnessTsModuleForTest`），随 draft 落盘——对齐老版 ~2,300 行测试交付物。
- plan 词汇补 `map`/fan-in/逐项 emit——老 rule-check 按 JR 扇出、resume-parser 批量处理在现有 7 种 action kind 下**结构性不可表达**。

**第三步：生产执行门（"真代码"从沙箱验证物变成生产运行形态）**
- `codeact.ts` 的 `-sb` 硬不变量升级为**策略门**：验收全绿（code_really_ran + execution_fidelity 通过）的 spec 允许 promote 后继续跑代码；保留 kill-switch 与 declarative 降级。当前悖论：验收门要求代码真跑，promote 又结构性剥夺跑代码的能力。
- API 实探教学回路：`probe_api` 大脑工具 + 人授权实拍报文 + 信封断言（`data.data.*` 嵌套、multipart-only 这类怪癖只有实探能发现——老版 CLAUDE.md 的教训原文）。
- 人机签核缺口：设计/代码层面的 park 门（现仅测试用例门）、结构化规则表单（阈值/评分表/去重优先级不该是自由文本 prompt）、人类教学跨 run 沉淀（askedQuestions 目前只活在单 run ctx）。
