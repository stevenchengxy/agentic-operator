# OntoCode 设计 Brief v2 · 极简版（整份即 prompt，直接完整粘贴）

## 任务

你是资深产品设计师。为 **OntoCode** 设计高保真可交互原型（首选单文件 HTML+CSS+少量 JS，深色，中文文案）。

OntoCode 面向 FDE（驻场交付工程师）：**把企业 Ontology（业务本体）编译成可部署的 agents 代码**（事件驱动 functions，跑在 Inngest 上）。用户描述场景（或只选一个 Ontology 域），一次生成一组互相接线的 agent，沙箱真跑验证，一键部署。用户是强技术人群，讨厌聊天式 AI 产品，需要上线证据，活在 git 里。

## 核心理念：一块屏、一列卡、其余皆抽屉

整个产品**只有一块屏**。稳态下屏幕上可见的东西 ≤ 6 个：顶栏、描述框、Generate 按钮、一列 agent 卡片、（可选的）一条横幅、（可选的）一行思考摘要。**没有左侧导航、没有常驻右栏、没有第二块屏。**

一切深内容都在**右侧滑出抽屉**里，点开才出现：agent 详情（代码/输入输出/运行记录）、修复提案、版本与回滚、完整思考 transcript、设置。

复杂度硬预算（违反即不合格）：
- 稳态可见组件 ≤ 6；
- 同一时刻横幅最多 1 条；
- 零常驻侧栏；
- 任何信息若当下无事发生，不得占据屏幕（预检通过不显示、无漂移不显示、无失败不显示）。

## 屏幕规格（自上而下）

### 1. 顶栏（一行）

`OntoCode`（Code 用品牌绿）· 域选择 chip `⬡ RAAS-v1 ▾`（下拉含：切换域 / 上传 Ontology JSON / 不用 Ontology）· `最近 ▾`（历史生成下拉）· `⚙`（弹层，仅 3 项开关：产物形态 Auto / 自动采纳推荐假设 开 / 沙箱验证后才可部署 开）· 右端状态位：稳态为 chip `已部署 v3 ✓`（点开=版本抽屉），有待部署变更时变为主按钮 `部署 v4`（绿色发光）。

### 2. 描述区

大输入框 + 回形针图标（统一上传入口：Ontology JSON / 样例数据 / 文档）+ 右端 `Generate ⌘↵`（生成中变 `⏹ 停止`）。空态时框下给 3 个推荐场景 chips（来自 Ontology）：「简历投递 → 解析 → JD 匹配 → 高分邀约（HR 审批）」「JD 变更时重算匹配分」「面试反馈汇总周报」。

### 3. 思考行（单行，条件出现）

生成中：`◐ 生成代码 3/6 · invite-drafter…`（蓝，带细进度条）；完成后折叠为一行灰字：`思考过程 · vs v3：2 修改 1 新增 3 未变 · 1m02s ↗`（点开=transcript 抽屉）。不生成时此行不存在。**思考过程永远不进主区正文。**

### 4. Agent 卡片列表（产品的心脏，唯一主体）

两列网格。每卡只有三行：**名称 + 状态 chip**、事件接线（等宽：`⚡ resume.parsed → match → ↦ match.scored`）、（仅当有变化时）一行变更说明。点卡片=打开详情抽屉。

状态 chip 是同一列卡片的「三种镜头」，按场景自动切换：

| 场景 | chip 示例 |
|---|---|
| 生成中 | `生成中…`（蓝） |
| 生成完待部署 | `新增`（绿）/ `修改`（琥珀，说明行：分数线 ~~≥80~~ → **≥75**）/ `未变`（灰） |
| 已部署稳态 | `✓ 142 runs`（绿，安静小字） |
| 运行失败 | `3 失败 · 修复 →`（红，点开=修复抽屉） |
| Ontology 漂移波及 | `漂移 · 重生成 →`（琥珀） |
| 用户手改过代码 | `🔒 手改`（紫，重生成自动跳过） |

示例卡片（6 个，招聘场景）：resume-parser、jd-matcher、invite-drafter、hr-approval-gate、invite-sender、ats-writeback（🔒 手改）。

### 5. 问题队列（AI 所有提问的唯一居所；条件出现，紧贴卡片列表下方）

AI 推理中产生的问题**不进对话流**——统一进入「问题队列」：一条琥珀横幅 `4 个问题 · 1 项必填 · 3 项已按推荐继续`，点开行内展开。每题是一张结构化行卡，含四样东西：**问题 + 为什么问**（溯源小字，如「规则 R-087 未给出阈值」）**+ 答案控件 + 影响范围**（如「改答案将重生成 jd-matcher 及下游 2 个」）。

四种类型，呈现方式不同：

1. **可推荐**（大多数）：已按绿色预选的推荐值生成完，改不改由用户。示例：「高分线？`≥80（推荐 · R-087）` `≥70` `自定义…`」
2. **无推荐、不阻塞**：不猜。相关 agent 照常生成但状态 chip 标灰色 `待补充`，队列中该题琥珀待答。示例：「你们的 ATS 是哪家？`Moka` `北森` `自定义…`」——回答后仅增量重生成受影响节点
3. **硬阻塞**（仅两类：缺凭证 / 写副作用授权）：红色必填。示例：「背调 API 凭证未配置——写副作用，不能替你猜 → `去配置` / `用测试 key`」
4. **追问**：回答引出的新问题排进**同一队列**，带小字「↳ 由上一答案引出」；永不形成线程、永不弹窗

已答项从队列消失，进「拍板记录」抽屉（答案 + 答题人 + 时间 + 溯源）——历史是审计记录，不是滚动对话。用户主动补充意图的入口只有两个且都是结构化挂载：**改描述框**（全局，触发增量重生成）、agent 详情抽屉内的**「补充指示」字段**（挂在该 agent 的 spec 上，局部重生成）。

### 6. 横幅位（条件出现，同一位置，最多 1 条）

- 漂移：`⚠ Ontology 已更新（快照 #12 → #14），影响 2 个 agent` + 主按钮 `重生成受影响 →`
- 失败聚类：`invite-sender 24h 内 3 次同因失败` + 主按钮 `查看修复提案 →`

### 抽屉（右侧滑出 ~480px，全部非常驻）

1. **Agent 详情**：3 个 tab——代码（含溯源注释 `// ← 假设 A-102 覆盖规则 R-087`；头部一行归属：`OntoCode 管理 · 手改将自动转入 🔒 保护` + `在 Git PR 中审阅 →`）/ 输入输出（端口表）/ 运行记录（最近 runs，深查外链）
2. **修复提案**：根因一句话（`503 被误判为永久错误未重试`）→ 补丁 diff（`-Set([429,502,504])` `+Set([429,502,503,504])` + 新增回归夹具一行）→ 按钮 `应用 → 沙箱 → 部署`（绿）/ `仅存草稿` / `去 Runs 深查 ↗`
3. **版本**：v3 当前 ← v2 ← v1 竖列，每版一行（时间/作者/沙箱证据），`回滚` 按钮
4. **Transcript**：完整思考过程（**只读的调试证据，不是交互面**；本设计只需占位示意）
5. **拍板记录**：已答问题的审计列表（答案/答题人/时间/溯源）
6. **设置**：即顶栏 ⚙ 弹层，同一内容

## 视觉语言

深色优先。背景 `#0b0d10`，面板 `#12161b/#171c22`，描边 `#242c35`，文字 `#e9eef3/#9aa7b4/#66717d`，品牌绿 `#45d19f`，琥珀 `#e8b34b`，红 `#e5534b`，蓝 `#5aa7e8`，紫 `#b18ae8`（各配 12% 透明浅底）。卡片圆角 12–16px、按钮胶囊形；代码/事件名/functionId 等宽字体，代码块底 `#0d1117`。徽章语义固定：绿=新增/健康，琥珀=修改/假设/漂移，灰=未变，紫=手改，红=失败/必填。

## 红线（违反任何一条即不合格）

✕ 聊天窗/对话流——禁止的是「时间线为主体的回合制消息流」；AI 的提问一律走问题队列，自由文本只存在于描述框、各题「自定义…」和 agent 抽屉「补充指示」，都是结构化挂载而非对话回合 ✕ 向导步骤 ✕ 思考流刷屏主区 ✕ 打断式确认弹窗 ✕ 常驻侧栏/第二块屏 ✕ DAG 拖拽画布 ✕ 通用 IDE 功能（代码出口是 Git PR）✕ 监控大盘（健康只是卡片上的一个 chip）

## 交付与验收

- 单文件 HTML 原型，桌面 1440px 为主，窄屏优雅降级为单列。
- 可交互演示 4 个状态：**空态**（描述框+推荐 chips，卡片区为空或显示已部署稳态）→ **生成中**（卡片渐次出现+思考行）→ **待部署**（diff chips+问题队列+部署按钮亮）→ **已部署稳态**（安静：卡片绿 chip，横幅无，思考行无）。外加至少 1 个抽屉实际可打开（建议：agent 详情或修复提案）。
- 用上文示例数据与中文文案，不用 lorem ipsum。
- 验收：① 稳态截图看起来接近「一个输入框 + 一列安静的卡片」；② 3 秒看懂「描述 → Generate → 部署」；③ 出事时界面才「长出」东西，事了恢复安静；④ 必填（红）与可忽略（琥珀）一目了然；⑤ 复杂度硬预算全部达标。
