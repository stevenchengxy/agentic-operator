# OntoCode 设计 Brief v7 · 任务台（整份即 prompt，直接完整粘贴）

## 任务

你是资深产品设计师。为 **OntoCode** 设计高保真可交互原型（单文件 HTML+CSS+少量 JS，深色，中文文案，桌面 1440px 为主）。若此前你做过 v1–v5：**v7 从零重建**，只继承下文明确点名的部分。

一句话定位：OntoCode 是一个**会推理、会调用工具的代码生成智能体**——通过企业 Ontology（业务本体）或用户的一句话描述，生成**能直接运行**的 agents 代码（事件驱动 functions，部署在 Inngest），并自带沙箱验证证据。用户是 FDE（驻场交付工程师）：强技术、讨厌聊天式 AI 产品、需要上线证据、活在 git 里。

## 核心结构：固定三拍，出口变形

**界面永远是固定的三拍，任何情景都不改变布局；变的只有第三拍里长出来的产物形态。**

```
┌─────────────────────────────────────────────────┐
│ ① 任务框（唯一入口，八种情景都从这进）                 │
├─────────────────────────────────────────────────┤
│ ② 执行行（单行原地刷新，展示推理与工具调用的当下）        │
├─────────────────────────────────────────────────┤
│ ③ 产物区（形态随情景变形；静息态=已部署套件的安静卡片）    │
│    └ 待你决定（条件出现的问题队列，紧贴产物区下方）       │
└─────────────────────────────────────────────────┘
```

不存在：左侧导航、常驻右栏、第二块屏、阶段条/流水线条、PR/merge 概念、聊天气泡。

## 规格

### 顶栏（一行，极简）

`OntoCode`（Code 用品牌绿）· 域 chip `⬡ RAAS-v1 · 快照 #12 ▾`（下拉：切换域/上传 JSON/不用）· `最近 ▾`（历史任务下拉）· `⚙`（弹层仅 3 项开关：产物形态 Auto / 自动采纳推荐假设 开 / 沙箱验证后才可部署 开）· 右端状态位：静息为 chip `已部署 v3 ✓`（点开=版本弹层：v3←v2←v1 竖列+回滚按钮），有待部署产物时变为发光绿按钮 `部署 v4`。

### 第一拍：任务框

大输入框 + 回形针（统一上传：Ontology JSON/样例/文档）+ 右端 `Generate ⌘↵`（执行中变红色 `⏹ 停止`）。占位文案轮换提示多情景：「描述一个场景…」「或：@某个 agent 改一处」「或：粘一段报错让我修」「或：只选域直接生成」。

**@ 引用**是关键机制：输入 `@` 弹出可引用对象（agent 名、失败 run、事件名），选中后成为框内 token。示例演示 `@jd-matcher`、`@run-8f2c`。空态时框下给 3 个推荐场景 chips（来自 Ontology 动作/规则）。

### 第二拍：执行行（反聊天的核心手法）

**单行、原地刷新、永不追加成日志。** 执行中：`◐ 正在调用 gohireMatchResumeApi · 探测响应结构`（蓝，左侧小转圈；下一步动作**替换**这一行）+ 右侧计量 `已 12 步 · 3 次工具调用 · ¥0.12` + `完整过程 ↗`（点开=只读 transcript 抽屉，占位示意即可）。完成后整行折叠为一行灰字：`✓ 完成 · 18 步 · 5 工具 · 2m41s · ¥0.42 ↗`。静息时此行不存在。

### 第三拍：产物区（五种形态 + 静息态）

**每个产物自带三件套：沙箱状态（`✓ 沙箱 6/6` / `◐ 验证中` / `✗ 1 失败`）· `测试` 按钮 · `部署` 按钮**——证据永远贴着代码走。

**形态 A · 套件网格**（情景 1/2/3/7）：两列 agent 卡。每卡=名称+状态 chip、事件接线（等宽 `⚡ resume.parsed → match → ↦ match.scored`）、（有变化时）一行变更说明。**卡片点击行内展开**（继承 v5 的正确决定）：步骤逻辑编号列表（1 监听 resume.parsed → 2 加载 JD `step.run "load"` → 3 调匹配 API `重试 3 次·指数退避` → 4 判定 ≥75 `分支：达标/不达标` → 5 发射 match.scored）+ 代码块（含溯源注释 `// ← 假设 A-102 覆盖规则 R-087`）。状态 chip 语义：`生成中…`蓝 / `新增`绿 / `修改`琥珀 / `未变`灰 / `🔒 手改`紫 / `✓ 142 runs`绿静 / `3 失败`红。示例 6 卡：resume-parser、jd-matcher、invite-drafter、hr-approval-gate、invite-sender、ats-writeback（🔒）。

**形态 B · 单函数面板**（情景 4）：一整块代码面板置顶（函数名 `score-on-parsed.ts`、事件接线一行、完整代码约 20 行含 `step.run`/重试注释），右上 `▶ 沙箱运行`，下方运行结果条 `✓ 用例通过 · 输入 resume.parsed 样例 → 输出 match.scored {score: 82}`。

**形态 C · 前后 diff**（情景 5）：只显示 jd-matcher 一张卡展开，代码 diff：`- if (score >= 80) {` / `+ if (score >= 75) {  // ← 本次任务修改`，上方一行影响说明：`下游 invite-drafter 触发条件联动更新（已包含）`。

**形态 D · 根因+补丁**（情景 6）：三段式——根因一句话（`503 被误判为永久错误未重试（trace 第 41 行 retryable=false）`）→ 补丁 diff（`-Set([429,502,504])` `+Set([429,502,503,504])` + `新增回归夹具 gohire-503-then-200.cassette`）→ 按钮 `应用 → 沙箱 → 部署`（绿）/ `仅存草稿`。

**形态 E · 漂移重对齐**（情景 8）：顶部一行 `Ontology 快照 #12 → 活库 #14：字段改名 jd.salary → jd.salaryRange`，下方受影响 2 卡的 diff（同形态 C），按钮 `全部应用`。

**静息态**：无任务时，产物区=当前已部署套件的安静卡片（绿 `✓ N runs` chip，无横幅无执行行）。**Day-2 事件不设专屏**：漂移/失败由系统投进「待你决定」。

### 待你决定（条件出现，紧贴产物区下方）

琥珀横幅 `待你决定 · 3（1 必填）`，点开行内展开。每题四要素：**问题 + 为什么问**（溯源小字）**+ 答案控件 + 影响范围**。四类：可推荐（绿色预选已继续）/ 无推荐不阻塞（相关卡标灰 `待补充`）/ 硬阻塞仅两类=缺凭证·写授权（红必填：「背调 API 凭证未配置 → `去配置`/`用测试 key`」）/ 追问（`↳ 由上一答案引出`，排同一队列不成线程）。系统投递的 Day-2 事项也在这里：`⚠ Ontology 已更新，影响 2 个 agent → [处理]`、`invite-sender 3 次同因失败 → [看补丁]`（点=生成一个新任务，走三拍）。已答项进「拍板记录」（状态位弹层里一个 tab，示意即可）。

## 从 v5 继承 / 抛弃

**继承**：agent 卡行内展开+步骤逻辑列表；徽章色语义；等宽技术 token；假设必填红/可推荐绿的区分。
**抛弃**：左侧导航（历史→顶栏「最近」；已部署第二屏→静息态+待你决定；模板库/客户切换 v7 不做）；常驻右栏「运行设置」（→ ⚙ 弹层 3 项）；Agents/事件链/代码 视图切换（事件链 v7 不做；代码在卡片展开里）。

## 验收

① 三拍结构在所有 8 个状态下布局完全不变，只有产物区内容变形；② 执行行任何时刻只有一行（截图连拍不出现堆叠）；③ 静息态接近「一个输入框 + 一列安静卡片」；④ 每个产物旁 3 秒内能找到「沙箱状态/测试/部署」；⑤ 必填（红）与可推荐（琥珀/绿）一目了然；⑥ 红线零违反。
